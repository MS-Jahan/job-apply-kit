# /make-resume

**User input:** `$ARGUMENTS`

Parse `$ARGUMENTS`:
- File path(s) to JDs (e.g., `JDs/*.txt`) → read files
- Multiple JD files or URLs → triggers Multi-Job Batch Mode
- "Quick:" prefix + JD path → run in Quick/Express Mode (skips checkpoints)
- Empty → ask user to paste JD or provide paths

---

Universal rules: `{{CORE_DIR}}/OPERATIONS.md` (#sources #truth #format #documents). Config keys read:
`cv_source`, `name`, `name_file`, `email_header`, plus the `## Resume preferences` prose (role types,
FIXED sections, bullet variants). This is the deep-tailoring track; the default flow for ordinary
applications is `create-template` + the apply skills — use this skill only on explicit request or a
combined-skill job (OPERATIONS #documents).

## Safety rules (always enforced)

**Accuracy > Relevance > Impact > ATS > Brevity**

Read config.md `## Truth gates` (`banned_claims`, `unproven_claims`) before generating any content.
Verify every claim against those lists and against `cv_source`.

- Use `email_header` from config.md in all outputs.
- Resume bullets: all variable bullets are 2L (CV: 2L/3L mix OK, check config.md `## Resume preferences`).
- Source ALL bullet content from `resume_builder/experience/` files (generated by `/setup-build-kb` from
  `cv_source`; never fabricate).
- Run `python3 {{RESUME_KIT_DIR}}/helpers/char_count.py` after each section — the tool is authoritative.

## User input during execution

If the user provides feedback, corrections or suggestions at any point:
1. Acknowledge it immediately.
2. If it affects an already-written section: go back, fix it, re-run the char-count gate.
3. If it changes the bullet plan: update the session file Bullet Plan.
4. If it is a question: answer it, then continue from the current step.
5. Never restart a phase — resume from the current position.

## Startup

Read `{{RESUME_KIT_DIR}}/reference/shared_ops.md` for session startup and derivation rules.
1. Read `<workspace>/SESSIONS.md` — check Active Sessions and KB corrections notes.
2. Read config.md — load `## Identity`, `## Resume preferences` (library path, output formats, role types).
3. If a session file exists for this JD: read it, check Status.
   - Phase 0 DONE, Phase 1 PENDING: resume at Phase 1.
   - Phase 1 DONE: resume at the Budget Gate.
   - Phase 2 IN_PROGRESS: read the generated file, check which sections exist, resume from the checkpoint.
   - Phase 2 DONE: "Resume already done. Run /make-cl next." Show the next command. Stop.
4. If no session file: detect single-job or multi-job batch mode and proceed to Phase 0.

## Quick Mode

Trigger: `$ARGUMENTS` starts with "Quick:"

Defaults:
- Select all HIGH priority achievements from the bundle's Priority Matrix as 2L.
- Fill remaining budget with MEDIUM priority in Priority Matrix order.
- Default format: 1-page resume (OPERATIONS #format page budget; a CV only when the JD clearly requires one).
- Skip the Phase 0 and Phase 1 stops.
- Keep the Budget Gate (auto-pass if within target) and the end-of-resume stop.
- Run all phases with progress commentary instead of interactive stops.

## Multi-Job Batch Workflow

Triggers if multiple JDs are provided or requested by the user. Reference `{{RESUME_KIT_DIR}}/support/multi_job_workflow.md`.

### Phase 0: Intake & Batch Initialization
1. Initialize batch directory: `output/batches/batch-{YYYY-MM-DD}-{slug}/` and state tracking file `_batch_state.json`.
2. Parse JDs to extract required skills, keywords, and domain requirements.
3. Match against the Experience Library.

### Phase 1: Aggregate Gap Analysis
1. Extract requirements from all JDs and cross-reference with the experience files in `resume_builder/experience/`.
2. Construct a unified, deduplicated gap map and save to `_aggregate_gaps.md`.

### Phase 2: Shared Experience Discovery
1. Present the aggregate gaps to the user.
2. Conduct a **single conversational branching interview** using the patterns in `{{RESUME_KIT_DIR}}/support/branching_questions.md` to resolve gaps.
3. Save the results to `_discovered_experiences.md` and append new items to the experience library so they are available for all jobs in the batch.

### Phase 3: Per-Job Processing (Sequential)
For each job in the batch:
1. Conduct research (WebSearch company background and benchmarking).
2. Create template skeleton.
3. Apply confidence-scored content selection (`matching_strategies.md`).
4. Generate the resume package (LaTeX and/or Markdown/DOCX) using the single-job Phase 2 rules.

### Phase 4: Batch Finalization
1. Generate `_batch_summary.md`.
2. Present all resumes for batch review. Upon approval, update the resume library with the tailored files.

## Single-Job Workflow

### Phase 0: Research & Session Setup
1. Read the target JD, `{{RESUME_KIT_DIR}}/reference/resume_reference.md` (budget targets), and config.md.
2. Run WebSearch queries (MANDATORY — 2-3 searches) to research the company culture, engineering values, and benchmarks.
3. Analyze the JD: classify requirements into **Direct**, **Bridge** (transferable), and **Gap**. Extract ATS keywords.
4. Setup folder `output/<FolderName>/` and write session file `session_<name>.md`.
5. **MANDATORY CHECKPOINT:** Present the success profile, framing strategy, and role classification to the user.
   **You MUST wait for the user's explicit text response before continuing.** Proceeding without
   confirmation misaligns the entire resume and requires full regeneration.

### Phase 0.5: Conversational Experience Discovery (Optional)
If gaps or low-confidence matches are found, and `Interactive gaps discovery` is enabled:
1. Ask the user if they'd like to run a discovery interview.
2. Ask targeted follow-up questions from `{{RESUME_KIT_DIR}}/support/branching_questions.md` to surface undocumented details.
3. Draft new resume bullets from their answers and write to `output/<FolderName>/discoveries.md`. Integrate approved bullets into `resume_builder/experience/` files.

### Phase 1: Plan Bullets (Matching & Selection)
1. Read experience files for the position and the target role bundle from `resume_builder/bundles/`.
2. Score every achievement against the JD using the scoring algorithm in `{{RESUME_KIT_DIR}}/support/matching_strategies.md`:
   - Direct Match (40%) | Transferable (30%) | Adjacent (20%) | Impact/Metric (10%)
3. Present the bullet plan table for each position (legend: `*` recommended, `o` available, `x` excluded/gap):

   | | ID | Achievement | Variant | Lines | JD Match |
   |---|---|-------------|---------|-------|----------|
   | * | P1-1 | [short description] | 2L | 2 | Direct |
   | o | P1-3 | [short description] | 2L | 2 | Bridge |
   | x | P1-7 | [short description] | -- | -- | Weak |

   Compare the recommended total against the budget card; show remaining slots and forced exclusions.
4. **MANDATORY CHECKPOINT:** Present the bullet plan table and budget.
   **You MUST wait for the user's explicit text response before continuing.** If you proceed without
   confirmation you will generate bullets the user did not approve.

## Budget Gate (after the user confirms the bullet plan, before Phase 2)

Re-read the confirmed Bullet Plan. Check the budget targets in `{{RESUME_KIT_DIR}}/reference/resume_reference.md`
Budget Card. Show `Budget: [N] bullets vs target [T]. PASS/FAIL`. **FAIL = do not proceed. Reconcile with the
user first.**

### Phase 2: Generate Resume
Restore context and load the appropriate template based on `config.md` output rules.

#### Path A: LaTeX Generation
1. Read LaTeX template (`{{RESUME_KIT_DIR}}/templates/resume_template.tex` or `cv_template.tex`) and `.cls`.
2. Populate summary, skills, and experience blocks (FIXED sections from config.md `## Resume preferences`
   are template-locked; only the VARIABLE sections are generated).
3. **Char Count Gate:** Run `python3 {{RESUME_KIT_DIR}}/helpers/char_count.py` after writing each position
   to ensure 1L, 2L or 3L bullets are within the target character limits. No OVER violations; last line of
   2L bullets >= 70% fill. Fix before the next position.
4. **Page Fill Gate:** resume <= 3 lines of white space on the last page; CV per the rendered-line target
   in `resume_reference.md`. If FAIL: add or trim variable bullets.
5. **Compile Gate:** `tectonic -X compile` (fallback `pdflatex`) to verify compiling. Verify pages match
   OPERATIONS #format (resume exactly 1 page, CV exactly 2). Use the Read tool to view the compiled PDF: check orphans, header wrapping, page
   fill. If FAIL: fix variable content, recompile.

#### Path B: Markdown / DOCX Generation
1. Read Markdown template `resume_template.md`.
2. Populate summary, skills, and experience sections.
3. If DOCX output is requested and the agent has document-export tooling available, produce it; otherwise deliver Markdown and say so plainly.
4. Generate the Resume Generation Report detailing coverage, reframings, and interview talking points.

## Post-Generation Checklist & Verification

Before completing, check the output files for:
- Correct Personal Info and contact header.
- Verb Discipline: hedge verbs for shared achievements.
- AI Fingerprints: Scan using `{{RESUME_KIT_DIR}}/support/ai_fingerprint_rules.md` (no generic AI filler, no banned words).
- Provenance Rules: Verify no unpublished papers are listed as published.

## Library Update (Phase 5)

Ask the user if they want to save the final resume to their library:
- **Option 1 (YES):** Copy the resume to the library folder (`resumes/`) and run a mini-build of the KB to index the new variations.
- **Option 2 (NO):** Leave files in `output/<FolderName>/` but do not index.
- **Option 3 (REVISIONS):** Request edits, modify source files, and regenerate.
